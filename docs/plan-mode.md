# Plan Mode — шаблон планирования сложных задач

Использовать для задач, затрагивающих **>3 файла** или **>5 шагов**.

## Алгоритм

1. **Исследование (read-only)** — изучить codebase, найти релевантные файлы
2. **Планирование** — написать `plan.md` в память сессии (не в проект!)
3. **Согласование** — показать пользователю план, получить approve / правки
4. **Реализация** — только после approve приступать к правкам

## Шаблон plan.md

```markdown
# План: [краткое название задачи]

## Контекст
Почему делаем эту задачу. Какой баг / фича.

## Подход
Кратко: что меняем и почему именно так.

## Файлы для изменения
| Файл | Что делать | Почему |
|------|-----------|--------|
| `path/to/file` | Добавить функцию X | Требуется для Y |

## Утилиты для переиспользования
- Уже есть `helper()` в `utils.py` — использовать его
- Модуль `auth` — добавить middleware туда

## Проверка
Как убедиться, что всё работает:
- [ ] Команда теста: `npm test`
- [ ] Ручная проверка: открыть страницу X, нажать Y
- [ ] Edge cases: пустой input, длинный текст

## Риски
- Может сломать Z → проверить перед deploy
- Зависит от PR #123 → подождать merge
```

## Правила read-only gate

- В режиме планирования: **только чтение и поиск**, правки запрещены
- Исключение: `plan.md` в `memory/` или `/tmp/` — можно писать
- После approve: обычный режим, правки разрешены
- Если пользователь сказал «сделай без вопросов» — пропустить Plan Mode

## Когда НЕ использовать

- Исправление опечатки в README
- Добавление одной кнопки по существующему паттерну
- Багфикс, где причина очевидна из stack trace
- Исследование и research — для этого read-only subagent
