

## Drawing-to-VOR: Quantity Extraction — Two Paths Forward

**Date**: 2026-07-08 ~16:20 GMT+8
**Status**: Awaiting user decision. Both paths documented.

---

### Current Situation
- Qwen-VL can accurately count elements **on plan views** (tested: Рсм1=13 ✅, БФм1=2 ✅)
- Fails on full document set because it cannot distinguish **plan views** from **sections/specifications**
- Reference quantities unavailable in production; user provides them only for training/error-checking

---

### Path 1: Manual Plan Selection (Quick Win)

**Workflow:**
```
User specifies which pages are plans (e.g., "листы 1,2,3 — планы")
  ↓
Script processes ONLY those pages with Qwen-VL (2000px)
  ↓
Accurate quantities extracted automatically
  ↓
Combined with auto-extracted marks, dimensions, rebar
  ↓
Final VOR generated
```

**Pros:**
- Fast to implement (today)
- High accuracy on known plan pages
- Low API cost (~$0.50 per drawing set)

**Cons:**
- Requires user input for each new drawing set
- Not fully autonomous

**Best for:** One-off or occasional use

---

### Path 2: Auto-Classification (Scalable)

**Workflow:**
```
OCR + heuristic classifier:
  - Keyword detection: "схема расположения", "план", "генплан" → plan
  - "разрез", "сечение", "узел" → section
  - "спецификация", "ведомость" → specification
  ↓
Auto-select plan pages
  ↓
Qwen-VL processes only plan pages
  ↓
Accurate quantities + full VOR
```

**Pros:**
- Fully autonomous
- Scales to any drawing set (КЖ5, КЖ6, КМ, etc.)
- No user intervention needed

**Cons:**
- Requires development time (~1–2 days)
- May need tuning for edge cases
- Higher initial complexity

**Best for:** Regular/repeated use
