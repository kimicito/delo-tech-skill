# AI-Native Container Logistics
## Интеллектуальный посредник для контейнерных перевозок металлургической группы

---

## Слайд 1: Зачем это нужно

**Металлургическая группа с 5 заводами перевозит 5000 контейнеров в месяц.**

Традиционная логистика требует **35–50 человек**, работающих в 3–5 отделах: закупка, ж/д, линии, документы, клиентский сервис. Информация теряется между отделами, реакция на сбои занимает дни, а скрытые потери (демерредж, простои, неоптимальные закупки) исчисляются сотнями тысяч долларов в год.

**Мы предлагаем другую модель.**

---

## Слайд 2: Что такое AI-Native

> «ИИ-агенты — это операционный персонал. Люди — руководители и контролёры.»

Компания проектируется с нуля вокруг принципа: каждый процесс изначально строится так, что агенты выполняют **90–95% рутинной работы**, а человек принимает решения, ведёт ключевые отношения и разбирает исключения.

Это не «цифровизация» существующей модели. Это **другая модель организации труда**.

## Слайд 4: 8 агентных контуров

### 1. Агент-покупатель
Мониторинг сотен владельцев парков и линий: ставки, условия, наличие. Сравнение, шорт-лист, шаблонные переговоры.

### 2. Агент-аналитик
Прогноз потребности по графикам производства. Упреждающая закупка вместо спешки.

### 3. Агент-коммуникатор
Вся переписка с поставщиками на их языке. Извлечение данных из писем. Объективный рейтинг партнёров.

### 4. Агент Ж/Д логист
Мониторинг платформ, стыковка по времени. Устранение главной точки потерь: «контейнер есть, платформы нет».

### 5. Агент-координатор линий
Бронирование вывоза, контроль демерреджа/детеншена, сверка счетов, план Б при сбоях.

### 6. Агент-интегратор заводов
Согласование окон подачи с 5 заводами. Синхронизация всей цепочки.

### 7. Агент-документооборота
Коносаменты, инвойсы, таможенные декларации для 50+ стран. Генерация, проверка, сверка.

### 8. Агент клиентского сервиса
Ответы «где контейнеры / когда прибудут» — мгновенно, 24/7.

## Слайд 6: Ключевые принципы

### 1. Данные с первого дня
Каждая ставка, подача, документ фиксируется структурно. **Данные = топливо агентов = актив компании.**

### 2. Human-in-the-loop
Агент готовит решение, человек подтверждает. Порог автономии растёт по мере доверия:
- Сначала: «агент предлагает»
- Потом: «агент делает в рамках лимитов»
- Затем: «агент делает, человек смотрит отчёт»

### 3. Сквозная связность
Все агенты работают на одном контуре данных: ж/д агент «знает» планы агента по контейнерам и агента по линиям.

### 4. Единый оркестр
Сбой в одной точке автоматически перестраивает план во всех связанных.

## Слайд 7: Организационная структура

```
Стратегия и отношения      2–3 чел.
  └── Ключевые партнёры, цены, контракты, риски

Контроль операций          4–6 чел.
  └── Надзор за агентами, разбор исключений (5–10% кейсов)

Доменные эксперты          2–3 чел.
  └── Ж/Д логистика, линии, таможня — экспертиза для нестандарта

Платформа                  1–2 чел. / подрядчик
  └── Данные, интеграции, развитие агентов

─────────────────────────────────────
Итого: 10–14 человек
(против 35–50 в классической модели)
```

## Слайд 8: Дорожная карта

### Этап 1: Фундамент (месяцы 1–3)
- Единое окно данных: все контейнеры, платформы, ставки, статусы
- Трекинг в реальном времени
- Агент документооборота (быстрый эффект, минимальный риск)

### Этап 2: Коммуникации (месяцы 3–6)
- Агент поиска ставок (собирает и ранжирует, человек выбирает)
- Агент-коммуникатор с поставщиками
- Контроль демерреджа/детеншена

### Этап 3: Координация (месяцы 6–9)
- Агент-интегратор заводов (окна подачи, синхронизация)
- Ж/Д агент (аренда платформ, стыковка)
- Клиентский портал для заводов и головной компании

### Этап 4: Автономия (месяцы 9–12)
- Прогнозирование объёмов
- Автономная диспетчеризация в рамках лимитов
- Оркестр: сквозное перепланирование при сбоях

## Слайд 9: Риски и защита

| Риск | Закрытие |
|------|----------|
| Ошибка агента в документах/бронировании | Human-in-the-loop на критичных операциях, лимиты автономии |
| Поставщики/линии без API | Агент работает через почту и парсинг кабинетов — это и есть его функция |
| Недоверие клиента | Прозрачность: клиент видит всё в реальном времени — это аргумент «за» |
| Зависимость от ИИ-платформы | Собственный слой данных и логики, модели заменяемы |
