### Формула РКЗФО

**Почему плохой запрос = плохой результат?**

```
❌ «Проверь этот договор»
→ Модель не знает: ты юрист или закупщик?
→ Не знает: что искать — риски, сроки, цены?
→ Не знает: для кого результат?
→ Ответ: общий, бесполезный шаблон

✅ «Ты — юрист. Найди топ-5 рисков для покупателя в этом договоре»
→ Роль задана → нужный стиль и глубина
→ Задача конкретна → фокус на рисках
→ Можно добавить формат → таблица/список
→ Результат: готовый рабочий материал
```

**5 элементов формулы:**

| Элемент | Что даёт | Пример |
|---------|----------|--------|
| **РОЛЬ** | Стиль, глубина, экспертиза | «Ты — аналитик закупок» |
| **КОНТЕКСТ** | Фокус, тон, специфика | «Алюминиевый завод, SAP, тендер на ₽50М» |
| **ЗАДАЧА** | Что именно сделать | «Сравни 3 КП по цене, сроку, рискам» |
| **ФОРМАТ** | Как представить результат | «Таблица + рекомендация» |
| **ОГРАНИЧЕНИЯ** | Границы, запреты, лимиты | «Не более 200 слов. Только факты из документа» |

> 💡 **Начни с РОЛИ — это одно слово, которое мгновенно повышает качество ответа на 50%.**

### Практика: РКЗФО в действии

**Пример 1 (Закупки):**
```
РОЛЬ: Ты — аналитик по промышленным закупкам РУСАЛ.
КОНТЕКСТ: Тендер на поставку катодных блоков, 3 поставщика.
ЗАДАЧА: Сравни 3 КП по цене, срокам, гарантии, рискам.
ФОРМАТ: Таблица (поставщик, критерий, оценка) + рекомендация.
ОГРАНИЧЕНИЯ: Только факты из КП. Не более 300 слов.
```

**Пример 2 (Юристы):**
```
РОЛЬ: Ты — корпоративный юрист.
КОНТЕКСТ: Договор поставки с новым поставщиком, мы — покупатель.
ЗАДАЧА: Найди топ-5 рисков для нашей стороны + отсутствующие защитные условия + готовые формулировки для замены.
ФОРМАТ: Таблица (риск, пункт договора, формулировка, приоритет 1-5).
ОГРАНИЧЕНИЯ: Ссылайся на конкретные пункты. Не домысливай.
```

**Пример 3 (Производство):**
```
РОЛЬ: Ты — эксперт по производственным процессам и надёжности оборудования.
КОНТЕКСТ: Алюминиевый завод, инцидент с краном 50 тонн, редуктор подъёма.
ЗАДАЧА: Проведи разбор инцидента методом 5Why или Ishikawa. Найди корневую причину.
ФОРМАТ: Дерево причин (таблица) → корневая причина → меры предотвращения.
ОГРАНИЧЕНИЯ: Укажи раздел-источник. Не домысливай технические параметры.
```

## Урок 0.2: Eval и работа с документами

### Что такое Eval?

**Eval (Evaluation) = проверка качества ответа самой моделью.**

```
Без eval:  Ты → запрос → ответ → принимаешь на веру
           Модель могла обобщить, выдумать деталь или пропустить риск

С eval:    Ты → запрос → ответ → eval-вопрос → улучшенный ответ
           Модель сама находит свои слабые места и исправляет их
```

**4 типа eval-вопросов — добавь в конец любого чата:**

| Тип | Вопрос | Что выявляет |
|-----|--------|-------------|
| **Самооценка** | «Оцени ответ 1–10: насколько выводы подкреплены фактами из запроса?» | Галлюцинации и обобщения |
| **Пробел** | «Что важного ты не учёл или пропустил в своём ответе?» | Слепые пятна |
| **Критик** | «Найди 3 слабых места в своём же ответе» | Допущения и неточности |
| **Альтернатива** | «Предложи принципиально другой подход к задаче» | Расширение диапазона решений |

**Пример Eval в действии (Закупки):**
```
Запрос: Сравни три КП на поставку катодных блоков.

Ответ модели (слабый):
«Поставщик А предлагает наименьшую цену, Б — лучшие сроки. 
Рекомендую А как наиболее экономичного. Риски: возможны задержки.»

Eval-вопрос:
«Оцени ответ 1–10. Что ты не учёл? 
Какие данные из КП проигнорировал? Есть ли риски репутации поставщика?»

Улучшенный ответ:
«Оценка 5/10. Не проверил: гарантии, историю поставок, форс-мажор. 
Поставщик А имеет 2 судебных иска за 2024 год. 
Рекомендую Б — выгода по рискам перевешивает разницу в цене 3,2%. 
Прилагаю таблицу по 6 критериям.»
```

### Работа с документами: настройки OWU

**Формат файла влияет на точность сильнее, чем промпт:**

| Формат | Точность | Примечание |
|--------|----------|------------|
| **PDF текстовый** | 5/5 ⭐ | Лучший вариант. Текст выделяется курсором. |
| **Word (.docx)** | 4/5 | Отлично читается. Используй стили заголовков. |
| **Excel (.xlsx)** | 2/5 | Ячейки теряют структуру. **Лайфхак: добавь первый лист с описанием таблиц.** |
| **Скан PDF** | 1/5 | Модель видит картинку. Точность ~20%. Нужен OCR перед загрузкой. |

**Настройки RAG (Admin -> Documents):**

| Параметр | Оптимально | Зачем |
|----------|-----------|-------|
| **Chunk Size** | 500-800 токенов | Финансовые таблицы: 400-600. Меньше = точнее. Больше = лучше контекст. |
| **Chunk Overlap** | 10-20% | Перекрытие между кусками. Предотвращает потерю данных на границах. |
| **Top K Results** | 5-8 кусков | Сколько фрагментов видит модель. Сложные запросы: 8-10. |
| **Temperature** | 0.1 - 0.2 | Для документов всегда низкая. Высокая = творчество = галлюцинации. |

> ⚠️ **Для Excel:** Добавь первый лист с текстом «Этот файл содержит: [описание таблиц и колонок].» Модель поймёт структуру и резко улучшит точность ответов по числовым данным.

---

### Как модель читает документ (RAG)

```
1. 📄 Документ загружен → PDF/Word/Excel в Knowledge Base
2. ✂️ Нарезка на куски → Документ режется на фрагменты по 500-800 слов
3. 🔍 Твой вопрос → OWU ищет куски, похожие на вопрос
4. 📦 Топ 5-8 кусков → Только они передаются модели — не весь файл
5. 💬 Ответ модели → Модель отвечает только по этим кускам
```

> 💡 **Главный вывод:** Модель видит только 5-8 кусков. Если нужный факт не попал — модель его не знает. **Длинный промпт с правилами + требование ссылки = фильтр галлюцинаций.**

## Урок 0.3: Настройка ассистента и шаблонов

### Системный промпт (готовый шаблон)

```
Ты — аналитик документов промышленного предприятия.

ПРАВИЛА РАБОТЫ С ДОКУМЕНТАМИ:
1. Отвечай ТОЛЬКО на основе загруженных файлов.
   Если нужной информации нет — скажи прямо:
   «В документе эти данные отсутствуют».
2. К каждому факту и цифре давай ссылку:
   раздел, страница или название таблицы.
3. НЕ дополняй ответ из общих знаний.
   НЕ интерпретируй то, чего нет в файле.
4. Таблицы воспроизводи точно, без округлений.
5. Если вопрос неоднозначен — уточни сначала.

ФОРМАТ ОТВЕТА:
— Прямой ответ (1-2 предложения)
— Подтверждение из документа со ссылкой
— Таблица если нужна — точно как в документе
— Итог: «Источник: [раздел / стр. N]»

САМОПРОВЕРКА ПЕРЕД ОТВЕТОМ (eval):
Перед тем как ответить, проверь себя:
— Все ли факты взяты из документа?
— Нет ли домысливания или общих слов?
— Есть ли ссылка на источник каждой цифры?
Если нет — перепиши ответ.
```

### Как настроить ассистента в OWU

**Шаг 1: Системный промпт**
```
📍 Workspace → Models → Edit → System Prompt

Пример для закупок:
«Ты — ассистент директора по закупкам РУСАЛ. 
 Всегда: таблица → риски → рекомендация. 
 Отвечай на русском.»
```

**Шаг 2: Knowledge Base**
```
📍 Workspace → Knowledge → New Knowledge

Загрузи: регламент закупок, типовой договор, прайс-лист.
Задай вопрос — получи ответ со ссылкой на раздел.
```

**Шаг 3: Промпт-шаблоны**
```
📍 В чате напечатай / и выбери из библиотеки

Пример: /анализ_КП → сразу запускает нужный промпт 
с полной формулой. 10 секунд вместо 2 минут набора.
```

### Правило 15 минут

> **Если задача заняла > 15 минут — сначала спроси OWU.**

**План формирования привычки:**

| Неделя | Что делать | Цель |
|--------|-----------|------|
| **1** | Замени одну задачу. Каждое утро — 1 задача через OWU вместо Google или Word. Анализ письма / черновик ответа / разбор документа. | Почувствовать разницу в скорости |
| **2** | Загрузи свои документы. Добавь в Knowledge Base регламент или шаблон своего отдела. Задавай вопросы по своим документам. | Ответы с отсылкой к вашему контексту |
| **3** | Поделись с командой. Покажи коллеге 1 приём, который тебе помог. Сохрани 3 промпта в библиотеку для команды. | OWU стал частью рабочего процесса |

### Внешние vs Внутренние модели

| | **ВНЕШНИЕ** (ChatGPT, Claude, Gemini, YandexGPT) | **ВНУТРЕННИЕ** (OpenWebUI on-premise) |
|---|---|---|
| **Где** | Облако | Закрытый контур компании |
| **Данные** | Уходят на серверы поставщика | Не покидают контур — полная безопасность |
| **Подходит для** | Анализ открытых данных, публичные документы, переводы, обучение, код, идеи | Внутренняя отчётность, КП, договоры, тендеры, кадры, инциденты, финансы |
| **Правило** | Имена, цифры, коммерческие данные → нет | Всё конфиденциальное → да |

> **Если в тексте есть имена, цифры, коммерческие данные или внутренние инциденты → только внутренняя модель.**
