## Урок 2.1: Автоматизация смет (ВОР → AI → Смета)

### Цель
Научиться использовать AI для проверки смет по ФЕР-2020/БИМ, поиска критических ошибок, которые человек пропускает. Работа с документами — only on-premise.

### Теория (15 мин)

**БИМ-методика (единственно правильная):**

| Статья | Сокращение | Индекс | Что входит | Ошибка если нет |
|--------|-----------|--------|-----------|-----------------|
| **Оплата труда** | ОТ (ОЗП) | INDEX_ZP ≈ 60-70 | Зарплата рабочих | Общий индекс → занижение в 7× |
| **Эксплуатация машин** | ЭМ | INDEX_MACH ≈ 15-20 | Амортизация, топливо | Общий INDEX_SMR → неверно |
| **Материалы** | М | INDEX_MAT ≈ 8-10 | Материалы, изделия | Материалы внутри расценки = ошибка |
| **Зарплата машинистов** | ЗПМ | INDEX_MACH | Внутри ЭМ | Забывают включить |
| **Транспорт затрат** | ТЗ | INDEX_MAT | Доставка | Пропускают при удалении |

**Формула текущей цены (БИМ):**
```
Текущая сумма = (ОТ × INDEX_ZP) + (ЭМ × INDEX_MACH) + (М × INDEX_MAT)
```

**НР и СП — от ФОТ, не от прямых:**
| | Неправильно | Правильно | Ошибка |
|---|------------|----------|--------|
| **База** | 15%/12% от прямых затрат | % от ФОТ (фонд оплаты труда) | Занижение в 10× |
| **Норматив** | Типовые 15%/12% | Шифр по типу работ (Пр/812-016.0-1) | Неправильная норма |
| **Пример** | НР = 15% × 10 000 = 1 500 | НР = 121% × ФОТ = 2 572 тыс.₽ | В 7× разница |

**Поправки (коэффициенты условий работ):**
| Поправка | ОТ | ЭМ | М | Применение |
|----------|-----|-----|-----|------------|
| **П.58 пр.б** (действующее здание) | 1.15 | 1.25 | 1.25 | Работа в эксплуатируемом здании |
| **Прил.10 т.5 п.1.2** (ограничения) | 1.35 | 1.35 | 1.35 | Работа в ограниченных условиях |
| **Итоговая** | 1.55 | 1.69 | 1.25 | Комбинированная |

> **Правило:** Применяется к базовой цене ДО индексирования. Коэффициенты по статьям — разные.

**ФССЦ — материалы отдельно:**
- ФЕР20-02-002-01 — монтаж решётки (без стоимости решётки)
- ФССЦ 19.2.03.07-0008 — стоимость решётки 150×150 = 12.84 ₽/шт

> **Правило:** Всё, что в ВОР → должно быть в смете. Всё, что в смете → должно быть в ВОР.

**5 критических ошибок (AI их находит, человек часто пропускает):**
1. Общий индекс вместо раздельных по статьям (ОТ, ЭМ, М)
2. НР/СП от прямых затрат вместо ФОТ
3. Пропущенные коэффициенты условий работ (П.58 пр.б, Прил.10)
4. Материалы внутри расценки вместо отдельно через ФССЦ
5. Возврат прихода не отражен в ЛКН АУСН

## Урок 2.2: Анализ чертежей и извлечение данных (ВОР)

### Цель
Научиться извлекать Ведомость объёмов работ из чертежей через AI-vision (Qwen-VL), проверять автоматически.

### Теория (15 мин)

**Pipeline извлечения ВОР:**
```
TIFF (300 DPI, A1) → preprocess.py → тайлы 1000×1000 (overlap 100px)
→ tile_ocr.py (Qwen-VL-OCR) → JSON (текст, таблицы, размеры)
→ extract_vor_final.py → CSV (марки, количества, размеры)
→ vor_reviewer.py → Report (PASS/FAIL)
```

**Типы элементов (расширенный список):**
| Марка | Элемент | Формула | Единица |
|-------|---------|---------|---------|
| СБН-XX-YYYY | Буронабивная свая | π × (D/2)² × L × n | м³ |
| Рсм1 | Ростверк | ширина × высота × длина × n | м³ |
| БФм1 | Балка фундаментная | длина (из чертежа) × n | м.п. |
| ФОм1 | Фундамент | площадь основания × высота | м³ |
| КП4 | Каркас перемычки | по спецификации | шт |
| Зд1 | Закладная деталь | по спецификации | шт |

**Проблемы OCR и решения:**
| Проблема | Причина | Решение |
|----------|---------|---------|
| Overcounting | LLM считает марки на разрезах как отдельные элементы | Только планы (layout pages), не разрезы |
| Крупные тайлы | 2000×2000 = один лист | Массовая обработка = галлюцинации | Проверка через vor_reviewer |
| Размеры | LLM не всегда точен | Человек проверяет критичные |
| Формулы | Может ошибиться в расчёте | Проверка reviewer + человек |

**Путь 1 (быстрый):** Пользователь указывает плановые листы → AI считает только их.
**Путь 2 (масштабируемый):** Авто-классификация листов → AI определяет план/разрез → считает только планы.

## Урок 2.3: Планирование и контроль сроков через AI-агенты

### Цель
Автоматизировать планирование графиков работ, критический путь, анализ отклонений. Генерация Gantt-диаграмм.

### Теория (15 мин)

**AI-планировщик:**
- Генерация графиков из текстового описания
- Автоматический расчёт критического пути (CPM)
- Предиктивная аналитика: риски срыва сроков
- Реакция на изменения: «Добавилась точка» → пересчёт за 10 сек

**Gantt-диаграмма:**
- Ось X: время (дни/недели)
- Ось Y: работы/задачи
- Столбцы: длительность, начало, конец, зависимости
- Критический путь: красным, без резерва
- Резервы: зелёным, можно сдвинуть

**Факторы риска срыва сроков:**
- Поставки материалов (задержка)
- Погода (бетонирование при +5°C и выше)
- Кадры (бригады, отпуска, болезни)
- Оборудование (поломки, ТО)
- Согласования (экспертиза, разрешения)
- Субподрядчики (качество, сроки)

## Системный промпт для строителей (готовый шаблон)

```

Специализация: сметы по ФЕР-2020, БИМ-методика, проверка проектной документации.

ПРАВИЛА РАБОТЫ СО СМЕТАМИ:
1. Всегда разделяй по статьям: ОТ, ЭМ, М, ЗПМ, ТЗ.

3. Коэффициенты условий работ применяй до индексирования.
4. Материалы основные — через ФССЦ, отдельно от монтажных.
5. Возврат прихода отражай в ЛКН АУСН.

ПРАВИЛА РАБОТЫ С ЧЕРТЕЖАМИ:

4. Сомнительные значения — отмечай [ПРОВЕРИТЬ].
```

## Практические кейсы для домашней работы

1. **Проверка сметы:** Загрузить реальную смету (или учебную). Найти 5 критических ошибок. Оценить финансовое влияние.
2. **ВОР из чертежа:** Загрузить чертёж (TIFF/PDF). Извлечь ВОР через pipeline. Проверить через vor_reviewer. Сравнить с сметчиком.
3. **График работ:** Создать график для реального объекта. Найти критический путь. Смоделировать 2 сценария задержки.
4. **БИМ-пересчёт:** Взять смету с общим индексом. Пересчитать по БИМ (раздельные индексы). Сравнить итоговые суммы.
5. **Системный промпт:** Создать ассистента для своего департамента в OpenWebUI. Протестировать на 3 реальных задачах.
