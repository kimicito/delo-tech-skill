## Урок 3.1: Анализ видео и распознавание объектов

### Цель
Научиться использовать AI-vision (Qwen-VL, LLaVA) для анализа видеозаписей, распознавания объектов, поведенческих паттернов. On-premise = данные не уходят в cloud.

### Теория (15 мин)

**Vision-модели на on-premise:**
- **Qwen-VL** — лучшая для OCR и детального анализа сцен
- **LLaVA** — хорошая для описания сцен и объектов
- **CogVLM** — альтернатива, хороша для китайских документов

**Типы анализа:**
| Тип | Что детектирует | Пример | Ограничения |
|-----|----------------|--------|-------------|
| **Объект-детекция** | Люди, машины, предметы | 3 человека, 2 автомобиля | Ложные срабатывания (тени, отражения) |
| **Поведенческий анализ** | Подозрительные действия | Осмотр забора, остановка у двери | Ночная съёмка, качество, угол |
| **Подсчет** | Посетители, транспорт | 15 человек за час | Перекрытия, скопления |
| **OCR на видео** | Номера, пропуска, номера | Номер автомобиля, штрих-код | Размытие, угол, освещение |
| **Сравнение** | «Было ли это лицо раньше?» | Розыск, white/black list | Разные углы, прическа, очки |

**Приватность и безопасность:**
- On-premise: данные не уходят на серверы OpenAI, Google, Яндекса
- Контур безопасности: открытые порты, доступ к моделям, логи
- Регуляторика: 152-ФЗ, хранение видео, доступ к биометрии
- Политика: сроки хранения, кто имеет доступ, удаление

**Ограничения AI-vision:**
- Ночная съёмка: точность падает на 30-50%
- Ложные срабатывания: тень, отражение, животные, погода
- Скорость: обработка кадра 1-3 секунды (не real-time для многих камер)
- Масштаб: 10+ камер = нужен кластер GPU

### Live Demo (15 мин)

**Сценарий:** Анализ скриншота с камеры наблюдения.

**Сценарий 1 (норма):**
> «Проанализируй изображение с камеры наблюдения. Парковка, 15:00, 5 машин, человек идет к входу с сумкой.»

**Промпт (анализ):**
```
Роль: Ты — система видеоаналитики службы безопасности.
Задача: Проанализируй изображение с камеры.

Формат анализа:
1. Общая сцена (что происходит, сколько людей, машин, типы)
2. Объекты (перечислить с координатами примерно: слева/справа/центр, даль/ближний план)
3. Поведение (обычное / подозрительное / требует внимания / критическое)
4. Риски (0-10 шкала, обоснование: почему этот уровень)
5. Рекомендации (стандартная процедура / усилить внимание / направить патруль / немедленный ответ)
6. Время обработки (если известно)

Пример хорошего ответа:
Сцена: Парковка объекта, день, хорошее освещение. 3 автомобиля, 2 человека.
Объекты: Автомобиль 1 (белый, седан, стоит у входа), Автомобиль 2 (черный, внедорожник, припаркован), Человек 1 (возле входа, ожидает), Человек 2 (у забора, осматривается).
Поведение: Человек 1 — ожидание (обычное). Человек 2 — осмотр периметра (подозрительно, требует внимания).
Риски: 4/10 — возможный осмотр периметра, но дневное время, хорошая видимость.
Рекомендация: Направить патруль для визуального контакта. Не тревога.
Время: [если известно]
```

**Сценарий 2 (подозрительно):**
> «Проанализируй: периметр, 02:00, машина с выключенными фарами, 2 человека у забора, один держит предмет в руках.»

**Сценарий 3 (инцидент):**
> «Проанализируй: склад, 10:30, дым в углу, человек бежит к выходу, пожарная сигнализация сработала.»

## Урок 3.2: Генерация отчетов и документации

### Цель
Автоматизировать создание протоколов, актов, рапортов с помощью AI. RAG на шаблонах, классификация инцидентов, временные линии.

### Теория (15 мин)

**Шаблоны документов СБ:**
| Документ | Когда | Обязательные поля |
|----------|-------|-------------------|
| **Протокол осмотра** | Каждый осмотр | Дата, время, место, кто осматривал, что обнаружено, фото, подписи |
| **Акт об инциденте** | Инцидент | Дата, время, место, описание, причины, последствия, меры, ответственные |
| **Рапорт начальнику** | Ежедневно/по событию | Краткое содержание, оценка, рекомендации, необходимые действия |
| **Журнал инцидентов** | Все инциденты | Классификация, уровень, статус, дата открытия/закрытия |
| **Заявление в полицию** | Преступление | Факты, доказательства, свидетели, ущерб, просьба |

**RAG на шаблонах:**
- Загрузить в Knowledge Base: 10 лучших протоколов, 5 актов, регламенты
- AI генерирует документ по аналогии, но с новыми данными
- Проверка: человек сверяет с оригиналом, подписывает

**Классификация инцидентов:**
| Класс | Уровень | Примеры | Действия |
|-------|---------|---------|----------|
| **Попытка проникновения** | 3-5 | Осмотр забора, подозрительные у двери | Усилить патрулирование, камеры, проверить логи |
| **Проникновение** | 4-5 | Несанкционированный вход | Задержание, полиция, полная проверка |
| **Кража** | 4-5 | Пропажа ТМЦ, оборудования | Задержание, инвентаризация, полиция, страховая |
| **Повреждение** | 2-4 | Вандализм, порча имущества | Фиксация, ремонт, камеры, заявление |
| **Пожар/ЧС** | 5 | Пожар, утечка, обрушение | Эвакуация, МЧС, полное расследование |
| **Конфликт** | 2-3 | Драка, угрозы, проникновение бытовое | Развод, охрана, медпомощь, полиция при необходимости |
| **Ложное срабатывание** | 1 | Животное, погода, сбой | Сброс, проверка, корректировка |

**Временные линии (timeline):**
- AI восстанавливает хронологию из фрагментов (видео, логи, показания)
- Формат: время → событие → источник (камера N, лог, свидетель)
- Gaps: указать [НЕТ ДАННЫХ], не домысливать

**Сценарий:** Несанкционированное проникновение на склад.

**Данные:**

Склад 5: дверь не взломана, но замок поцарапан. Инвентаризация: пропало 2 ноутбука, 3 мобильных телефона. Сумма ущерба ~150,000₽. Охранник (Иванов) отвлекся на звонок в 23:30. Свидетели: нет.»

**Промпт (генерация пакета):**
```

Задача: Создать полный пакет документов по инциденту.

Исходные данные:
[вставить данные]

Требования:

   - Дата, время, место

   - Сроки (когда доложить)

## Урок 3.3: Аналитика угроз и паттернов

### Цель
Научиться использовать AI для предиктивной аналитики, выявления паттернов, трендов, аномалий. Heatmap, корреляция, прогноз.

### Теория (15 мин)

**Паттерн-анализ:**
| Паттерн | Что ищем | Пример | Действие |
|---------|---------|--------|----------|
| **Временной** | Часы/дни пиковой активности | Большинство инцидентов в пт 23:00-02:00 | Усилить патрулирование в эти часы |
| **Пространственный** | Зоны риска | Камера 12, 7, 3 — 70% событий | Установить дополнительные камеры, освещение |
| **Поведенческий** | Последовательность действий | Осмотр → ожидание → попытка | Обучить охрану, алгоритм реагирования |
| **Корреляционный** | Связь с внешними факторами | Инциденты растут при отпусках | Усилить контроль в отпускной период |
| **Аномалийный** | Отклонение от нормы | Внезапный рост событий на 300% | Расследование, усиление, анализ причин |

**Предиктивная модель:**
- Факторы: день недели, погода, события, сезон, штат
- Вероятность: «На следующей неделе ожидается 2-3 инцидента уровня 2-3»
- Точность: не 100%, но лучше интуиции + показывает тренды

**Heatmap:**
- Ось X: часы (0-23)
- Ось Y: дни недели (пн-вс)
- Значение: частота инцидентов (цвет: зеленый → желтый → красный)
- Применение: планирование патрулей, распределение ресурсов

**Аномалия-детекция:**
- Отклонение от среднего на 2+ стандартных отклонения
- Пример: обычно 2 инцидента/неделю, сейчас 8 — аномалия
- Действие: расследование, а не паника

Данные (3 месяца, CSV или текст):

Требования:
1. Паттерны:
   - Временные: какие дни/часы пиковые? (если данных по часам нет — укажи [НЕТ ДАННЫХ])
   - Корреляция с погодой (мороз = больше? оттепель = меньше?)
   - Корреляция с событиями (праздники, ремонт, отпуска)
   - Корреляция со штатом (неполный = больше инцидентов?)
   - Тренд: растет, падает, стабильно?

2. Heatmap (текстовый ASCII):
   - Дни недели × часы = частота инцидентов
   - Если данных по часам нет — создать гипотетический heatmap на основе типичных паттернов (указать, что гипотетический)

3. Аномалии:
   - Какие месяцы отклоняются от среднего на 2+ сигмы?
   - Возможные причины (связать с факторами)
   - Рекомендации (усилить, расследовать, наблюдать)

4. Прогноз на следующий месяц (Июль):
   - Ожидаемое количество инцидентов (диапазон: мин, среднее, макс)
   - Уровень риска (низкий/средний/высокий)
   - Рекомендации по ресурсам (патрули, камеры, охрана)
   - Факторы риска (что может увеличить число)
   - Факторы защиты (что может уменьшить)

5. Рекомендации:
   - Какие меры усилить (конкретно, по времени/зонам)
   - Когда усилить патрулирование (дни/часы)
   - Какие камеры/датчики проверить/добавить
   - Какие процедуры обновить

Формат: Аналитическая записка (2-3 страницы), таблицы, выводы, рекомендации. Не домысливай. Если не хватает данных — [НЕДОСТАТОЧНО ДАННЫХ].
```

## Системный промпт для СБ (готовый шаблон)

```
Ты — аналитик службы безопасности промышленного предприятия с 5-летним стажем.
Специализация: видеоаналитика, предиктивная аналитика, документирование инцидентов.

ПРАВИЛА АНАЛИЗА:
1. Всегда разделяй факты и предположения. Факты — без пометок. Предположения — отметь [ПРЕДПОЛОЖЕНИЕ].
2. Не делай выводов о виновности. Только факты и наблюдения.
3. Если данных недостаточно — указать [НЕДОСТАТОЧНО ДАННЫХ]. Не домысливать.
4. Риски оценивай по шкале 0-10 с обоснованием (почему этот уровень).
5. Классификация: норма (1-2) / подозрительно (3-4) / инцидент (4-5) / критическое (5).

ПРАВИЛА ДОКУМЕНТОВ:
1. Протокол: все обязательные поля (дата, время, место, кто, что, фото, подписи).
2. Рапорт: факты отдельно, предположения отдельно, рекомендации конкретные.
3. Журнал: классификация, уровень, статус, даты, ответственный, меры.
4. Все документы: официальный тон, без эмоций, строгий.

ФОРМАТ АНАЛИЗА ВИДЕО:
— Сцена (время, место, освещение, погода)
— Объекты (люди, машины, предметы — количество, описание, расположение)
— Поведение (обычное / подозрительное / требует внимания / критическое)
— Риски (0-10, обоснование)
— Рекомендации (нет / наблюдение / патруль / задержание / вызов полиции / эвакуация)
— Доказательственная ценность (стандартный срок / срочно архивировать)

ФОРМАТ АНАЛИТИКИ:
— Паттерны (временные, пространственные, поведенческие, корреляционные)
— Тренд (растет/падает/стабильно, процент, период)
— Аномалии (отклонение, возможные причины, действия)
— Прогноз (диапазон, уровень риска, рекомендации)
— Рекомендации (конкретные, по времени/зонам/ресурсам, сроки)

САМОПРОВЕРКА (eval):
Перед ответом:
— Все ли факты подтверждены данными?
— Нет ли выводов о виновности?
— Риски обоснованы (не интуиция)?
— Рекомендации конкретны и выполнимы?
— Если прогноз — указан диапазон (не точное число)?
```
