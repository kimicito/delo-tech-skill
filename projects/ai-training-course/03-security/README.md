## Урок 3.1: Анализ видео и распознавание объектов

### Цель
Научиться использовать AI-vision для анализа видеозаписей, распознавания объектов и поведенческих паттернов.

### Теория (15 мин)
1. **Vision-модели на on-premise** — Qwen-VL, LLaVA, CogVLM
2. **Типы анализа:**
   - Объект-детекция (люди, машины, предметы)
   - Поведенческий анализ (подозрительные действия)
   - Подсчет (посетители, транспорт)
   - OCR на видео (номера, номера пропусков)
3. **Приватность** — on-premise = данные не уходят в cloud
4. **Ограничения** — точность, ложные срабатывания, ночная съемка
5. **Контур безопасности** — открытые порты, доступ к моделям

### Live Demo (15 мин)
- Загрузка скриншота с камеры в OpenWebUI
- Анализ: "Что происходит на изображении?"
- Детекция: "Сколько людей? Какая активность?"
- Сравнение: обычная ситуация vs подозрительная
- Генерация описания для протокола

### Hands-on (20 мин)
**Задание:** Проанализировать 3 сценария

**Промпт-шаблон для видеоаналитики:**
```
Роль: Ты — система видеоаналитики службы безопасности.
Задача: Проанализируй изображение с камеры наблюдения.

Формат анализа:
1. Общая сцена (что происходит, сколько людей, машин)
2. Объекты (перечислить с координатами примерно)
3. Поведение (обычное / подозрительное / требует внимания)
4. Риски (0-10 шкала, обоснование)
5. Рекомендации (стандартная процедура / усилить внимание / немедленный ответ)

Пример ответа:
Сцена: Парковка объекта, 3 автомобиля, 2 человека
Объекты: Автомобиль 1 (белый, седан), Автомобиль 2 (черный, внедорожник), 
         Человек 1 (возле входа), Человек 2 (у забора)
Поведение: Человек 1 — ожидает у входа (обычное). Человек 2 — осматривает забор (подозрительно)
Риски: 4/10 — возможный осмотр периметра
Рекомендация: Направить патруль для визуального контакта
```

### Сценарии для практики

**Сценарий 1 (норма):**
```
"Проанализируй: парковка, 15:00, 5 машин, человек идет к входу с сумкой"
```

**Сценарий 2 (подозрительно):**
```
"Проанализируй: периметр, 02:00, машина с выключенными фарами, 
 2 человека у забора, один держит предмет в руках"
```

**Сценарий 3 (инцидент):**
```
"Проанализируй: склад, 10:30, дым в углу, человек бежит к выходу, 
 пожарная сигнализация сработала"
```

### Чек-лист
- [ ] 3 сценария проанализированы
- [ ] Риски оценены по шкале 0-10
- [ ] Рекомендации даны по процедурам
- [ ] Время анализа каждого: < 30 секунд

## Урок 3.2: Генерация отчетов и документации

### Цель
Автоматизировать создание протоколов, актов, рапортов с помощью AI.

### Теория
1. **Шаблоны документов** — в OpenWebUI: загрузить шаблон, AI заполняет
2. **Структура протокола** — стандартные разделы, обязательные поля
3. **RAG на документах** — поиск по базе протоколов, аналоги
4. **Классификация инцидентов** — автоматическая категоризация
5. **Временные линии** — восстановление хронологии из фрагментов

### Live Demo
- Генерация протокола осмотра по записям с камер
- Создание рапорта о происшествии из голосового описания
- Сравнение с шаблоном — проверка полноты
- Автоматическая классификация по типу инцидента

### Hands-on
**Задание:** Создать полный пакет документов по инциденту

**Промпт:**
```
Роль: Ты — дежурный по службе безопасности. 
Опыт: составление протоколов, актов, рапортов по ГОСТ Р 59641-2021.

Задача: Создать полный пакет документов по инциденту.

Исходные данные (голосовое описание или заметки):
"Вчера в 23:45 камера 12 зафиксировала движение у периметра. 
Патруль прибыл в 23:52. Обнаружены следы у забора, 
высота 1.8м, появились после 22:00 (по записи). 
Нарушений не обнаружено, объект цел."

Требования:
1. Протокол осмотра места происшествия
   - Дата, время, место
   - Обстоятельства
   - Описание обнаруженного (с фото-фиксацией)
   - Действия патруля
   - Заключение
2. Рапорт начальнику СБ
   - Краткое содержание
   - Оценка риска
   - Рекомендации (усиление, замена камеры, ничего)
3. Запись в журнал инцидентов
   - Классификация (попытка проникновения / ложное срабатывание / подготовка)
   - Уровень (1-5)
   - Статус (закрыт / в работе / на контроле)

Формат: Официальный, строгий, без эмоций, только факты.
```

### Расширенное задание
**RAG-поиск по базе инцидентов:**
```
"Проанализируй базу инцидентов за последний год:
- Сколько попыток проникновения?
- Какие часы пиковой активности?
- Какие камеры чаще срабатывают?
- Тренд: растет или падает?
- Сравнение с прошлым кварталом

Формат: Аналитическая записка для руководства (1 страница)"
```

### Чек-лист
- [ ] Протокол составлен по ГОСТ
- [ ] Рапорт с оценкой и рекомендациями
- [ ] Журнал заполнен корректно
- [ ] Классификация и уровень определены
- [ ] Проверка руководителем СБ

## Урок 3.3: Аналитика угроз и паттернов

### Цель
Научиться использовать AI для предиктивной аналитики, выявления паттернов и трендов.

### Теория
1. **Паттерн-анализ** — повторяющиеся сценарии, временные паттерны
2. **Предиктивная модель** — вероятность инцидента по факторам
3. **Heatmap** — карта рисков по территории/времени
4. **Корреляция** — связь между событиями (погода, дни недели, события)
5. **Аномалия-детекция** — отклонение от нормального поведения

### Live Demo
- Анализ логов камер за месяц — поиск паттернов
- Генерация heatmap: когда и где чаще всего срабатывают камеры
- Прогноз: "На следующей неделе ожидается..."
- Сравнение: AI-прогноз vs реальность (прошлый квартал)

### Hands-on
**Задание:** Проанализировать данные и сделать прогноз

**Промпт:**
```
Роль: Ты — аналитик службы безопасности, специализация: предиктивная аналитика.

Задача: Проанализировать данные и сделать прогноз.

Данные (в формате CSV или текст):
Месяц | Инциденты | Попытки проникновения | Ложные срабатывания | Погода | События
Янв | 12 | 3 | 7 | мороз | праздники
Фев | 8 | 1 | 5 | мороз | нет
Мар | 15 | 5 | 8 | оттепель | ремонт дороги
Апр | 10 | 2 | 6 | дождь | нет
...

Требования:
1. Паттерны:
   - Корреляция с погодой (мороз = больше?)
   - Корреляция с событиями
   - Временные паттерны (часы, дни недели)
2. Heatmap (текстовый):
   - Дни недели × часы = частота инцидентов
3. Прогноз на следующий месяц:
   - Ожидаемое количество инцидентов
   - Уровень риска (низкий/средний/высокий)
   - Рекомендации по ресурсам
4. Рекомендации:
   - Какие меры усилить?
   - Когда усилить патрулирование?
   - Какие камеры проверить?

Формат: Аналитическая записка (2-3 страницы), таблицы, выводы.
```

### Чек-лист
- [ ] Паттерны идентифицированы и подтверждены данными
- [ ] Heatmap создана
- [ ] Прогноз обоснован статистикой
- [ ] Рекомендации конкретны и выполнимы
