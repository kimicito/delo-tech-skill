## Урок 4.1: AI для сравнения цен и подбора аналогов

### Цель
Научиться использовать AI для автоматического сравнения цен поставщиков, поиска аналогов, TCO-анализа. Работа с конфиденциальными данными — только on-premise.

### Теория (15 мин)

**Price Comparison Pipeline:**
```
Excel (5 позиций) → API/поиск цен (2 поставщика) → Аналоги (другая марка + тот же бренд, отклонения) → TCO-анализ → Red Team (риски) → Excel (3 вкладки)
```

**Типы аналогов:**
| Тип | Что ищем | Пример | Когда использовать |
|-----|----------|--------|-------------------|
| **Другая марка** | Полный аналог, другой производитель | Huawei S5735 вместо Cisco C9200 | Когда оригинал слишком дорог, сроки не подходят |
| **Тот же бренд, отклонения** | Та же марка, параметры ±10% | Cisco C9200-24T (без PoE) вместо C9200-24P | Когда PoE не нужен, экономия 20% |
| **Refurbished** | Восстановленное, гарантия | Cisco Renewed, 1 год | Для не-критичных систем, бюджет ограничен |
| **Совместимое** | Не оригинал, но совместимо | SFP compatible module | Для расходников, аксессуаров |

**TCO (Total Cost of Ownership) — стоимость владения:**
```
TCO = Цена закупки + Доставка + Установка/настройка + Гарантийное обслуживание (3 года) + Расходники + Обучение персонала + Вывод из эксплуатации
```

> **Правило:** Цена закупки — это 30-50% TCO. Дешевый аналог может быть дороже в эксплуатации.

**Red Team анализ рисков для каждого аналога:**
| Риск | Что проверить | Критичность |
|------|--------------|-------------|
| **Совместимость** | Работает с существующим оборудованием? | Критично |
| **Гарантия в РФ** | Есть сервис, запчасти, инженеры? | Критично |
| **Срок поставки** | Стабильный? Не 3 месяца из Китая? | Важно |
| **Репутация** | Отзывы, судебные иски, банкротства? | Важно |
| **Документация** | Русская инструкция, поддержка? | Важно |
| **Обновления** | Прошивки, security patches? | Важно |
| **Вывод** | Ликвидность, утилизация? | Не критично |

**Кэширование результатов:**
- Цены сохраняются, обновляются по расписанию
- Аналоги сохраняются в базу знаний
- Отчеты генерируются автоматически

```
   - Гарантийное обслуживание в РФ (сервисные центры, инженеры)
   - Срок и стабильность поставок
   - Репутация и отзывы (возможные риски)
   - Документация и поддержка (русская, обучение)

   - Итоговый риск (высокий/средний/низкий, обоснование)

5. TCO-анализ (3 года) для каждого варианта:
   - Цена оборудования
   - Доставка и установка
   - Гарантийное обслуживание (стоимость, если не входит в цену)
   - Техподдержка (если платная)
   - Расходники (SFP, кабели, БП)
   - Обучение персонала (если нужно)
   - Итоговая TCO (3 года)

6. Рекомендация:
   - Лучший вариант для покупки (с обоснованием)
   - Лучший вариант по TCO (может отличаться)
   - Лучший аналог (если бюджет ограничен)
   - Что проверить дополнительно (список)
   - Когда пересмотреть (срок, триггеры)

Формат: Таблицы + текстовый анализ. Только факты. Если цена неизвестна — ориентировочно, отметить [ОРИЕНТИРОВОЧНО].
```

## Урок 4.2: Оптимизация маршрутов и складской логистики

### Цель
Научиться использовать AI для оптимизации доставок, планирования загрузки складов, прогнозирования спроса. Задача коммивояжера с ограничениями.

### Теория (15 мин)

**Маршрутизация — задача коммивояжера с ограничениями:**
```
Минимизировать: время + пробки + топливо + износ
При ограничениях: грузоподъемность, объем, окна доставки, температурный режим, хрупкость, опасный груз
```

**Факторы, которые AI учитывает:**
| Фактор | Почему важно | Как AI помогает |
|--------|-------------|-----------------|
| **Пробки** | Задержка, переплата водителю | Исторические данные + пробки в реальном времени |
| **Окна доставки** | Клиент не примет раньше/позже | Планирование с жесткими временными рамками |
| **Грузоподъемность** | Перегруз = штраф, опасность | Распределение по машинам, маршруты |
| **Температурный режим** | Бетон +5°C, еда +2...+6°C | Тип машины, скорость, маршрут, время |
| **Хрупкость** | Плитка, стекло, сантехника | Порядок погрузки, дороги, скорость, крепление |
| **Опасный груз** | ADR, сопровождение, маршрут | Дороги, населенные пункты, заправки, парковки |
| **Возврат** | Пустой рейс = убыток | Backhaul (груз на обратном пути), маршрут |

**Складская оптимизация:**
| Задача | Что оптимизируем | AI-метод |
|--------|-----------------|----------|
| **Зонирование** | Расстояние от входа до частых товаров | ABC-анализ, частота обращения, сезонность |
| **Размещение** | Тяжелое внизу, хрупкое отдельно, химия отдельно | Правила + оптимизация |
| **Пиковая загрузка** | Время обработки заказа, очереди | Прогноз, распределение, буферные зоны |
| **Пополнение** | Когда заказывать, сколько | Прогноз спроса, точка заказа, EOQ |
| **Резервы** | Буферный запас, страховой | Сезонность, lead time, вариативность |

**Прогноз спроса:**
- Факторы: сезонность, тренд, маркетинг, конкуренты, экономика
- Методы: скользящее среднее, экспоненциальное сглаживание, ARIMA, ML
- AI: автоматический выбор метода, адаптация к изменениям
- Точность: 70-90% для стабильных товаров, 50-70% для новых

### Live Demo (15 мин)

**Сценарий:** Доставка строительных материалов по Москве.

**Промпт (маршрутизация):**
```
Роль: Ты — логист по доставке строительных материалов. Опыт: 5+ лет, оптимизация маршрутов, снижение стоимости доставки на 15-30%.

Задача: Построить оптимальный маршрут доставки.

Данные:
- Склад: МКАД, 65 км (55.7558, 37.6173)
- Машина: Газель, 1.5 тонн, 12 м³, хрупкое — верхний ярус
- Водитель: Иванов, опыт 3 года, смена 8 часов (с 8:00)

Точки доставки:
1. Объект А (Тушино, 55.85, 37.45): 500 кг плитки (хрупкое), окно 9:00-12:00
2. Объект Б (Марьино, 55.65, 37.75): 300 кг клея, 200 кг грунта, окно 10:00-14:00
3. Объект В (Бутово, 55.55, 37.60): 400 кг сантехники (хрупкое), окно 13:00-17:00
4. Объект Г (Химки, 55.90, 37.45): 200 кг инструментов, гибкое окно
5. Дополнительно: заехать за 100 кг песка (Зеленоград, 55.98, 37.18, 15 мин на погрузку, гибкое окно)

Требования:
1. Оптимальный маршрут (минимум км, учет пробок, окна, время водителя)
2. Порядок погрузки (что вниз, что верх, что в кабину, вес распределения)
3. Время на каждую точку (прибытие, разгрузка, отъезд, buffer)
4. Запас топлива (проверить, хватит ли, с учетом пробок)
5. Стоимость (топливо, амортизация, зарплата водителя, итог)
6. Риски (что может пойти не так, план Б для каждого риска)
7. Рекомендации (как улучшить: другая машина, другой водитель, другой маршрут)

Формат: Таблица маршрута (этап, время, км, груз, действия) + схема погрузки (вид сверху) + timeline + стоимость + риски + рекомендации.
```

**Расширенный сценарий:**
> «Сценарий: Заказчик Объекта Б просит перенести доставку на 16:00 (после окна). Пересчитай маршрут. Что сдвинется? Какие окна нарушатся? Сколько добавится км и времени?»

**Промпт (склад):**
```
Роль: Ты — складской менеджер. Оптимизация размещения, ABC-анализ, снижение времени обработки на 20-30%.

Задача: Оптимизировать размещение.

Данные:
- Склад: 500 м², 4 стеллажа (2 этажа), 2 зоны (приемка, отгрузка)
- Товаров: 200 SKU (строительные материалы)
- ABC-анализ: A (20% SKU, 80% оборота), B (30%, 15%), C (50%, 5%)
- Ограничения: химия отдельно, тяжелое внизу, хрупкое отдельно, холодильник 2 м³
- Типичный заказ: 5-10 SKU, 50-200 кг, 30-120 мин на сборку

Требования:
1. Зонирование (план склада, вид сверху ASCII):
   - Зона приемки (вход, разгрузка, проверка)
   - Зона отгрузки (выход, погрузка, проверка)
   - Стеллаж 1: A-класс (частые, быстрый доступ)
   - Стеллаж 2: B-класс (средние)
   - Стеллаж 3: C-класс (редкие, дальше)
   - Стеллаж 4: Химия, хрупкое, холодильник

2. ABC-распределение по стеллажам (таблица: SKU, класс, стеллаж, ярус, зона, примечание)

3. Рекомендации по размещению новых SKU (алгоритм: частота → вес → хрупкость → химия)

4. Прогноз: хватит ли места через 6 месяцев (тренд +20% SKU, +30% оборот)
   - Сколько места нужно?
   - Какие зоны расширить?
   - Какие товары вынести на внешний склад?

5. Проблемы: что затормозит работу (узкие места) и как решить

Формат: Схема размещения (ASCII, вид сверху) + таблица + рекомендации + прогноз.
```

```
2. Порядок погрузки (вид сверху, ASCII: что внизу, что верху, что в кабине)

4. Время: хватит 8 часов? Запас на пробки (20%)?
5. Окна: все соблюдены? Если нет — какие нарушены и что делать?
6. Топливо: расход 15 л/100км, цена 55₽/л. Стоимость?
7. Стоимость доставки: топливо + амортизация (5₽/км) + зарплата водителя (2000₽/смена). Итог?
8. Рекомендации: как улучшить (другая машина, разделить на 2 рейса, изменить окна)?

Формат: Таблицы + схема + расчеты + рекомендации.
```

**Проверка (чек-лист):**
- [ ] Маршрут оптимизирован (время, км, топливо)
- [ ] Погрузка спланирована (хрупкое, тяжелое, вес/объем)
- [ ] Грузоподъемность и объем не превышены
- [ ] Окна доставки соблюдены (или нарушения указаны и решены)
- [ ] Время смены не превышено (с запасом 20%)
- [ ] Стоимость посчитана (топливо, амортизация, зарплата)
- [ ] Рекомендации конкретны (другая машина, разделить, изменить окна)
- [ ] Eval: оценка реалистичности ≥ 7/10

## Урок 4.3: Автоматизация тендеров и документации

### Цель
Автоматизировать подготовку тендерной документации, проверку контрактов, анализ предложений. RAG на шаблонах, проверка рисков.

### Теория (15 мин)

**Тендерный документ — структура:**
1. Общие положения (наименование, заказчик, место, сроки)
2. Технические требования (параметры, ГОСТ/ТУ, сертификаты)
3. Количественные параметры (таблица: наименование, единица, количество, примечание)
4. Требования к поставщику (опыт, гарантия, сервис, финансовые)
5. Условия контракта (оплата, поставка, приемка, штрафы, форс-мажор)
6. Критерии оценки (цена, сроки, качество, гарантия, сервис — веса)
7. Приложения (спецификации, чертежи, формы, бланки)

**AI-проверка тендерного предложения:**
| Проверка | Что ищем | Критичность |
|----------|----------|-------------|
| **Полнота** | Все пункты ТЗ отражены? | Критично |
| **Арифметика** | Сходятся суммы, количества? | Критично |
| **Цены** | Неопределенные («по факту», «ориентировочно»)? | Критично |
| **Сроки** | Неясные («в течение месяца»)? | Критично |
| **Ответственность** | Ограниченная, непропорциональная? | Важно |
| **Штрафы** | Нет штрафов за просрочку? | Важно |
| **Приемка** | Неясные условия, споры? | Важно |
| **Форс-мажор** | Слишком широкий/узкий? | Важно |
| **Гарантия** | Срок, условия, что входит? | Важно |
| **Сервис** | Замена брака, ремонт, обучение? | Важно |

**Сравнение 3 предложений:**
- Не только цена! Цена = 40-60%, остальное = сроки, гарантия, сервис, репутация
- TCO: дешевый поставщик может быть дороже в эксплуатации
- Риски: новый поставщик с низкой ценой = риск срыва, брака, отсутствия сервиса
- Рекомендация: обоснованная, с цифрами, не «подешевле»

**Промпт (генерация ТЗ):**
```

1. Общие положения
   - Наименование закупки
   - Заказчик (название, контакты)
   - Место поставки (адрес, условия приемки)
   - Сроки поставки (этапы, общий срок, неустойка)

   - Опыт (аналогичные объекты, от 3 лет)

   - Сертификаты (ISO, ГОСТ, пожарная безопасность)

5. Условия контракта
   - Оплата (аванс 30%, постоплата 70% после приемки, или аккредитив)
   - Поставка (партиями, сроки, условия Incoterms)

   - Форс-мажор (определение, уведомление, сроки, разрешение споров)
   - Страхование (при транспортировке, ответственность)

6. Критерии оценки
   - Цена (вес 50%)
   - Сроки поставки (вес 20%)
   - Гарантия и сервис (вес 20%)

   - Чек-лист приемки

Формат: Официальный документ, структурированный, готовый для публикации. Таблицы, списки, нумерация. Не домысливать. Если данные неизвестны — [УТОЧНИТЬ].
```
