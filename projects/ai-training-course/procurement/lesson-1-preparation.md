# Урок 1: Подготовка закупки
## AI для закупщиков и логистов | Модуль "Закупки" | Урок 1 из 3

> **Формат:** 1.5 часа (теория 30 мин + Live Demo 30 мин + Практика 30 мин)
> **Практика после:** Домашнее задание на реальном кейсе
> **Цель:** Научиться готовить ТЗ, запрашивать цены, формировать конкурентный лист с помощью ИИ.

---

## Часть 1: Теория — как ИИ помогает в подготовке (30 мин)

### 1.1. Что такое Generative AI простыми словами

**Аналогия:**
> Вы задаёте вопрос очень опытному коллеге, который прочитал тысячи документов, участвовал в сотнях закупок и помнит всё. Он отвечает за секунды, не устаёт, не болеет, работает 24/7.

**Ключевое отличие от поисковика (Яндекс/Google):**

| Поисковик | Generative AI |
|-----------|---------------|
| Находит ссылки на документы | Создаёт готовый документ |
| Вы сами читаете и обобщаете | AI обобщает за вас |
| 10 ссылок → 2 часа чтения | 1 ответ → 2 минуты проверки |
| Не понимает контекст вашей компании | Понимает, если загрузить документы |

**Почему OpenWebUI (а не ChatGPT):**
- Ваши ТЗ, КП, договоры, цены — не уходят на серверы OpenAI/Google
- Работаем в закрытом контуре компании
- Можно загрузить внутренние регламенты, шаблоны, историю закупок

### 1.2. Интерфейс OpenWebUI — 5 минут до первого результата

**Где находится:**
```
Браузер → [внутренний адрес компании] → Логин/пароль (как в корп. системе)
```

**Главные элементы (показать на скриншоте/экране):**

| Элемент | Где | Зачем |
|---------|-----|-------|
| **Новый чат** | Слева сверху | Начать разговор |
| **История** | Слева | Вернуться к старым чатам |
| **Поле ввода** | Внизу | Писать запросы |
| **Скрепка 📎** | В поле ввода | Прикрепить файл (ТЗ, КП, договор) |
| **Выбор модели** | Вверху | Llama/Mistral — для текста, Qwen — для китайских поставщиков |
| **Настройки** | Вверху справа | Тонкие настройки (temperature, system prompt) |

**Первый запрос (попробовать вместе):**
```
Привет! Я закупщик в компании [название]. 
Помоги мне составить техзадание на закупку офисных стульев 
для 50 сотрудников. Какую информацию тебе нужно?
```

> 💡 **Не бойтесь экспериментировать.** Неправильных запросов нет — есть просто разные результаты. AI — ваш помощник, а не экзаменатор.

### 1.3. Формула РКЗФО — как говорить с ИИ на одном языке

**Проблема:** "Проверь договор" → слабый ответ. Почему? ИИ не знает:
- Кто вы? (юрист, закупщик, директор?)
- Что искать? (риски, цены, сроки?)
- Для чего? (для согласования, для переговоров?)
- В каком формате? (таблица, текст, письмо?)

**Решение — 5 элементов:**

| Элемент | Что даёт | Пример для закупщика |
|---------|----------|----------------------|
| **РОЛЬ** | Стиль и экспертиза | "Ты — закупщик с 10-летним стажем" |
| **КОНТЕКСТ** | Ситуация | "Внутренняя коммерческая закупка, бюджет до 2 млн ₽" |
| **ЗАДАЧА** | Что сделать | "Составь ТЗ на поставку светильников LED" |
| **ФОРМАТ** | Как оформить | "Таблица + список требований + форма заявки" |
| **ОГРАНИЧЕНИЯ** | Границы | "Без ссылок на 44-ФЗ, только внутренние требования" |

> 🔑 **Главное правило:** Начинайте с РОЛИ. Это одно слово повышает качество ответа на 50%.

**Пример: плохо → хорошо**

```
❌ "Напиши ТЗ на кабель"
→ Общий шаблон, неприменимый к вашей ситуации

✅ "Роль: Ты — ведущий инженер-электрик. 
Контекст: Жилой комплекс на 240 квартир, внутренние сети. 
Задача: Составить ТЗ на поставку силового кабеля ВВГнг-LS. 
Формат: Таблица с марками, сечениями, длинами + требования к поставщику. 
Ограничения: Без ГОСТ-ссылок, только параметры и проверки."
→ Готовое ТЗ, которое можно отправить поставщику
```

### 1.4. Eval — как ИИ проверяет сам себя

**Зачем:** AI может что-то упустить, недодумать или обобщить. Eval — это когда вы просите ИИ найти свои ошибки.

**4 вопроса (добавляйте в конец важных задач):**

| Вопрос | Что выявляет | Когда использовать |
|--------|-------------|-------------------|
| "Оцени ответ 1–10" | Галлюцинации, домыслы | Для важных документов |
| "Что ты не учёл?" | Слепые пятна | Когда много параметров |
| "Найди 3 слабых места" | Неточности, допущения | Для ТЗ, договоров |
| "Предложи другой подход" | Альтернативы | Когда не уверены в решении |

**Пример Eval для ТЗ:**
```
[После получения ТЗ от ИИ]

Оцени своё ТЗ 1–10. 
Какие технические параметры ты мог упустить? 
Что ещё должен указать заказчик для точности? 
Какие риски для поставщика не учтены в требованиях?
```

### 1.5. Фишки OpenWebUI для закупщика

**Фишка 1: Загрузка файлов (📎)**
- Загружайте старые ТЗ — ИИ повторит структуру
- Загружайте прайсы — ИИ извлечёт цены и сравнит
- Загружайте договоры — ИИ найдёт риски

**Фишка 2: System Prompt (настройка ассистента)**
```
Настройки → System Prompt:
"Ты — ассистент закупщика. Всегда используй таблицы. 
Структура ответа: анализ → риски → рекомендация. 
Если данных мало — укажи, что нужно уточнить."
```
→ Каждый чат будет работать по вашим правилам.

**Фишка 3: Шаблоны промптов (/)**
```
/ → Создать шаблон "ТЗ на закупку"
→ В следующий раз: /ТЗ → готовый промпт
```
→ Экономия 5-10 минут на каждый запрос.

**Фишка 4: Knowledge Base**
- Загрузите внутренние регламенты закупок
- Загрузите шаблоны ТЗ
- Загрузите историю закупок
→ ИИ будет отвечать с учётом ваших правил.

## Часть 2: Live Demo — показываем на экране (30 мин)

### Демо 1: Составление Технического Задания (10 мин)

**Сценарий:** Нужно купить светильники LED для нового офиса.

**Шаг 1 — базовый запрос (показать, что получится):**
```
Составь ТЗ на закупку светильников LED для офиса 500 м².
```
→ Показать результат (общий, шаблонный).

**Шаг 2 — улучшенный запрос (показать разницу):**
```
РОЛЬ: Ты — инженер по освещению с опытом проектирования офисов.
КОНТЕКСТ: Офис 500 м², open space, 60 рабочих мест, 8 переговорок, 
          2 кухни, коридоры. Работа 24/7 (2 смены).
ЗАДАЧА: Составить техническое задание на поставку и монтаж светильников.
ФОРМАТ: 
  1. Общие требования (площадь, высота потолков, освещённость по СНиП)
  2. Технические параметры (таблица: зона, тип, мощность, цветовая температура, количество)
  3. Требования к поставщику (опыт, гарантия, сертификаты)
  4. Условия поставки и монтажа (сроки, этапы, оплата)
  5. Форма заявки (таблица для заполнения поставщиком)
ОГРАНИЧЕНИЯ: Только LED, экономия энергии ≥ 40% vs люминесцентные.
```

**Шаг 3 — Eval (улучшаем результат):**
```
Оцени ТЗ 1–10. Что ты не учёл в контексте 24/7 работы? 
Какие дополнительные требования нужны для кухонь? 
Какие параметры лучше уточнить у заказчика?
```

**Результат:** Готовое ТЗ, которое можно отправить поставщикам.

### Демо 2: Запрос цен и формирование конкурентного листа (10 мин)

**Сценарий:** Получили 3 ответа от поставщиков на наше ТЗ.

**Шаг 1 — загружаем файлы (если есть):**
```
[Загрузить 3 PDF/Excel с КП через скрепку]

Проанализируй 3 коммерческих предложения. 
Выдели: цена за единицу, срок поставки, гарантия, условия оплаты, 
стоимость монтажа. Сведи в таблицу.
```

**Шаг 2 — или текстом (если файлов нет):**
```
РОЛЬ: Ты — аналитик закупок.
КОНТЕКСТ: Внутренняя коммерческая закупка светильников LED.
ЗАДАЧА: Сформировать единый конкурентный лист из 3 предложений.

Данные:
Поставщик А: Панель LED 600×600 40W — 1250 ₽/шт, срок 3 дня, 
             гарантия 2 года, оплата 50/50, монтаж 300 ₽/шт
Поставщик Б: Панель LED 600×600 36W — 980 ₽/шт, срок 14 дней, 
             гарантия 1 год, оплата 100% предоплата, монтаж нет
Поставщик В: Панель LED 600×600 40W — 1100 ₽/шт, срок 7 дней, 
             гарантия 3 года, оплата 30/70, монтаж 250 ₽/шт

Требования:
1. Таблица сравнения (поставщик, цена, срок, гарантия, оплата, монтаж, итого за 50 шт)
2. Критерии оценки (веса: цена 40%, срок 20%, гарантия 20%, условия 20%)
3. Рейтинг по каждому критерию
4. Итоговый рейтинг
5. Рекомендация с обоснованием

ФОРМАТ: Excel-подобная таблица (разделители |). Только факты.
```

**Шаг 3 — Eval:**
```
Какие риски ты не учёл при сравнении? 
Что ещё нужно проверить у поставщиков? 
Какие скрытые затраты могут быть?
```

### Демо 3: Поиск поставщиков (10 мин)

**Сценарий:** Нужно найти поставщиков кабеля ВВГнг-LS в Москве.

**Запрос:**
```
РОЛЬ: Ты — закупщик электротехнической продукции.
ЗАДАЧА: Составить список потенциальных поставщиков.

Требования:
- Продукт: кабель ВВГнг-LS (силовой, негорючий, малодымный)
- Регион: Москва и МО (доставка до складов на МКАД)
- Требования: собственное производство или прямые договоры с заводами, 
  гарантия, сертификаты пожарной безопасности
- Что нужно: название компании, сайт, контакты, ассортимент, 
  примечания (плюсы/минусы)

ФОРМАТ: Таблица (компания, сайт, телефон, ассортимент, плюсы, минусы, приоритет 1-5)
ОГРАНИЧЕНИЯ: Только реальные компании, которые работают в РФ. 
Не выдумывай контакты. Если не уверен — укажи [уточнить].
```

> ⚠️ **Важно:** ИИ может выдумать контакты или компании. Всегда проверяйте реальность найденного.

## Часть 3: Практика — участники делают сами (30 мин)

### Задание 1: Составить ТЗ (15 мин)

**Условие:**
> Ваша компания открывает новый склад 1000 м². Нужно осветить зону приёмки, зону хранения (стеллажи 6м высотой), зону отгрузки, офис на 5 человек, санузлы.

**Задача:**
1. Откройте OpenWebUI → Новый чат
2. Напишите запрос по формуле РКЗФО (минимум: Роль, Задача, Формат)
3. Получите ТЗ
4. Задайте Eval-вопрос: "Что ты не учёл?"
5. Получите улучшенное ТЗ

**Чек-лист проверки:**
- [ ] ТЗ содержит технические параметры (мощность, количество, тип)
- [ ] Указаны требования к поставщику
- [ ] Есть условия поставки/монтажа
- [ ] Форма заявки для поставщика
- [ ] После Eval добавлены недостающие пункты

### Задание 2: Конкурентный лист (15 мин)

**Условие:**
> Получили 3 предложения на кабель ВВГнг-LS 3×2.5 мм², 5000м:
> - Поставщик А: 45 ₽/м, 2 дня, ГОСТ, гарантия 1 год
> - Поставщик Б: 38 ₽/м, 5 дней, ТУ, гарантия 6 мес
> - Поставщик В: 42 ₽/м, 3 дня, ГОСТ+пожарный сертификат, гарантия 2 года

**Задача:**
1. Сформулируйте запрос на сравнение (таблица + критерии + рейтинг)
2. Получите конкурентный лист
3. Задайте Eval-вопрос про риски
4. Получите итоговую рекомендацию

**Чек-лист проверки:**
- [ ] Таблица сравнения по всем критериям
- [ ] Веса критериев (сумма 100%)
- [ ] Рейтинг каждого поставщика
- [ ] Учтены риски (ГОСТ vs ТУ, сертификаты)
- [ ] Рекомендация обоснована

## Практика после занятия (домашнее задание)

### Задание: Реальный кейс

**Выберите одну из своих текущих закупок (или ближайшую планируемую):**
1. Составьте ТЗ с помощью ИИ
2. Проведите Eval (улучшите ТЗ)
3. Если есть КП — сформируйте конкурентный лист
4. Если нужно найти поставщиков — попробуйте через ИИ (проверьте реальность!)

**Формат сдачи:**
- Скриншот диалога с ИИ
- Итоговый документ (ТЗ или конкурентный лист)
- Короткое резюме: "Что получилось, что не получилось, сколько времени сэкономил"

**Дедлайн:** До следующего занятия (Урок 2: Анализ и выбор).

## Материалы для тренера

### Подготовка к уроку:
- [ ] Доступ к OpenWebUI (тестовый аккаунт для демо)
- [ ] 3 готовых файла КП (PDF или текст) для демо сравнения
- [ ] Шаблон ТЗ (старый, для демонстрации загрузки файла)
- [ ] Слайды (опционально): 5-7 слайдов с формулой РКЗФО и примерами

### Распорядок 90 минут:
| Время | Что делаем |
|-------|-----------|
| 0:00-0:05 | Приветствие, цели, ожидания |
| 0:05-0:15 | Теория: что такое ИИ, отличие от поисковика |
| 0:15-0:25 | Интерфейс OWU, первый запрос |
| 0:25-0:35 | Формула РКЗФО с примерами |
| 0:35-0:45 | Eval, фишки OWU (файлы, шаблоны, Knowledge Base) |
| 0:45-0:55 | **Демо 1:** Составление ТЗ (плохо → хорошо → Eval) |
| 0:55-1:05 | **Демо 2:** Конкурентный лист (3 КП → таблица → рейтинг) |
| 1:05-1:15 | **Демо 3:** Поиск поставщиков (предупреждение о выдумках) |
| 1:15-1:30 | **Практика:** Задание 1 (ТЗ) + Задание 2 (конкурентный лист) |
| 1:30-1:35 | Обсуждение результатов, типичные ошибки |
| 1:35-1:40 | Домашнее задание, вопросы |

### Типичные ошибки участников:
1. **Слишком короткий запрос** → общий ответ. Решение: добавить РОЛЬ.
2. **Забывают Eval** → упущенные риски. Решение: напомнить про 4 вопроса.
3. **Верят выдуманным контактам** → ИИ может придумать. Решение: всегда проверять.
4. **Не загружают файлы** → ручной ввод. Решение: показать скрепку 📎.

## Промпт-шаблоны для закупщика (сохранить в OWU)

### Шаблон 1: ТЗ на закупку
```
РОЛЬ: Ты — [инженер/закупщик/специалист].
КОНТЕКСТ: [описание объекта, ситуации, бюджета].
ЗАДАЧА: Составить техническое задание на поставку [наименование].
ФОРМАТ:
  1. Общие требования
  2. Технические параметры (таблица)
  3. Требования к поставщику
  4. Условия поставки
  5. Форма заявки
ОГРАНИЧЕНИЯ: [бюджет, сроки, ограничения].
```

### Шаблон 2: Конкурентный лист
```
РОЛЬ: Ты — аналитик закупок.
ЗАДАЧА: Сформировать конкурентный лист из [N] предложений.

Данные:
[вставить данные по каждому поставщику]

Требования:
1. Таблица сравнения (поставщик, цена, срок, гарантия, условия, итого)
2. Критерии оценки (веса: цена [N]%, срок [N]%, гарантия [N]%, условия [N]%)
3. Рейтинг по каждому критерию
4. Итоговый рейтинг
5. Рекомендация с обоснованием

ОГРАНИЧЕНИЯ: Только факты. [ОРИЕНТИРОВОЧНО] если неизвестно.
```

### Шаблон 3: Поиск поставщиков
```
РОЛЬ: Ты — закупщик [категории].
ЗАДАЧА: Составить список потенциальных поставщиков [продукта] в [регионе].

Требования:
- Регион: [город/регион]
- Ассортимент: [что нужно]
- Требования: [собственное производство, гарантия, сертификаты]

ФОРМАТ: Таблица (компания, сайт, контакты, ассортимент, плюсы, минусы, приоритет)
ОГРАНИЧЕНИЯ: Только реальные компании. Не выдумывать контакты. 
[уточнить] если не уверен.
```
