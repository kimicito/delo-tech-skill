## Слайд 3: Что такое Generative AI? Простая аналогия

### Аналогия для понимания:

> Представьте, что вы задаёте вопрос **очень опытному коллеге**, который:
> - Прочитал тысячи документов
> - Участвовал в сотнях закупок
> - Помнит всё и не устаёт
> - Отвечает за секунды
> - Работает 24/7

### Это не поисковик:

| Поисковик (Яндекс/Google) | Generative AI (OpenWebUI) |
|---------------------------|---------------------------|
| Находит ссылки на документы | Создаёт готовый документ |
| Вы сами читаете и обобщаете | AI обобщает за вас |
| 10 ссылок → 2 часа чтения | 1 ответ → 2 минуты проверки |
| Не понимает контекст компании | Понимает, если загрузить документы |

## Слайд 4: Почему именно OpenWebUI?

### Главное преимущество — безопасность данных

**Ваши данные НЕ уходят наружу:**
- ❌ Не отправляются в ChatGPT (OpenAI, США)
- ❌ Не отправляются в Яндекс GPT (Яндекс, РФ)
- ❌ Не отправляются в Google (Gemini, США)
- ✅ Работаем в закрытом контуре компании
- ✅ Сервер стоит внутри, данные остаются внутри

### Что можно загружать без опасений:
- Внутренние регламенты закупок
- Коммерческие предложения поставщиков
- Договоры и приложения
- Прайс-листы с реальными ценами
- Технические задания

### Как работает:
```
Ваш компьютер → Внутренний сервер компании → Ответ
                (OpenWebUI + локальная модель)
```

## Слайд 5: Интерфейс OpenWebUI — 5 главных элементов

| Элемент | Где находится | Зачем нужно |

## Слайд 6: Формула РКЗФО — говорите с ИИ на одном языке

### Проблема: почему "проверь договор" = плохой запрос?

**ИИ не знает:**
- **Кто вы?** (юрист, закупщик, директор, инженер)
- **Что искать?** (риски, цены, сроки, технические параметры)
- **Для чего?** (для согласования, для переговоров, для тендера)
- **В каком формате?** (таблица, текст, письмо, протокол)

### Решение — 5 элементов формулы:

| Элемент | Что написать | Пример для закупщика |
|---------|--------------|----------------------|
| **РОЛЬ** | Кто вы? | "Ты — закупщик с 10-летним стажем" |
| **КОНТЕКСТ** | Ситуация | "Внутренняя коммерческая закупка, бюджет до 2 млн ₽" |
| **ЗАДАЧА** | Что сделать | "Составь ТЗ на поставку светильников LED" |
| **ФОРМАТ** | Как оформить | "Таблица + список требований + форма заявки" |
| **ОГРАНИЧЕНИЯ** | Границы | "Без ссылок на 44-ФЗ, только внутренние требования" |

> 🔑 **Главное правило:** Начинайте с РОЛЬ. Это одно слово повышает качество ответа на 50%.

```
РОЛЬ: Ты — ведущий инженер-электрик.
КОНТЕКСТ: Жилой комплекс на 240 квартир, внутренние электросети. 
          Внутренняя коммерческая закупка.
ЗАДАЧА: Составить техническое задание на поставку силового 
        кабеля ВВГнг-LS.
ФОРМАТ: 
  1. Общие требования (марки, ГОСТ/ТУ, сертификаты)

  3. Требования к поставщику (опыт, гарантия, сертификаты)
  4. Условия поставки (сроки, этапы, оплата)
```

**Результат:** Готовое ТЗ, которое можно отправить поставщику. С таблицами, параметрами, формой заявки.

## Слайд 8: Eval — как ИИ проверяет сам себя

### Зачем нужен Eval?

AI может:
- Что-то упустить (забыть про гарантию)
- Обобщить важную деталь
- Домыслить то, чего нет в контексте

**Eval = просим ИИ найти свои ошибки и исправить их**

### 4 вопроса Eval (добавляйте в конец важных задач):

| Вопрос | Что выявляет | Когда использовать |
|--------|-------------|-------------------|
| **"Оцени ответ 1–10"** | Галлюцинации, выдуманные факты | Для ТЗ, договоров, решений |
| **"Что ты не учёл?"** | Слепые пятна, упущенные параметры | Когда много технических деталей |
| **"Найди 3 слабых места"** | Неточности, допущения | Для договоров, рисков |
| **"Предложи другой подход"** | Альтернативные решения | Когда не уверены в решении |

### Пример Eval для ТЗ:
```
[После получения ТЗ от ИИ]

Оцени своё ТЗ по шкале 1–10. 
Какие технические параметры ты мог упустить? 
Что ещё должен указать заказчик для точности спецификации? 
Какие риски для поставщика не учтены в требованиях?
```

**Результат:** ИИ находит слабые места и предлагает улучшения.

## Слайд 9: Фишки OpenWebUI для закупщика

### 4 фишки, которые экономят часы:

**Фишка 1: Загрузка файлов (📎)**
```
Как: Нажмите скрепку → выберите файл → задайте вопрос
```
- Загружайте старые ТЗ → ИИ повторит структуру
- Загружайте КП от поставщиков → ИИ извлечёт цены и сравнит
- Загружайте договоры → ИИ найдёт риски

**Фишка 2: System Prompt (настройка ассистента)**
```
Где: Настройки → System Prompt
```
Пример:
```
Ты — ассистент закупщика. Всегда используй таблицы. 
Структура ответа: анализ → риски → рекомендация. 
Если данных мало — укажи, что нужно уточнить.
```
→ Каждый чат будет работать по вашим правилам.

**Фишка 3: Шаблоны промптов (/)**
```
Как: Сохраните хороший промпт → введите "/" → выберите
```
→ Экономия 5-10 минут на каждый запрос.

**Фишка 4: Knowledge Base (База знаний)**
```
Как: Workspace → Knowledge → New Knowledge → загрузите файлы
```
- Загрузите внутренние регламенты закупок
- Загрузите шаблоны ТЗ
- Загрузите историю закупок
→ ИИ будет отвечать с учётом ваших правил.

## Слайд 10: Демо 1 — Составление ТЗ

### Сценарий: нужно купить светильники LED для нового офиса

**Шаг 1 — базовый запрос (показываем, что получается):**
```
Составь ТЗ на закупку светильников LED для офиса 500 м².
```
**Результат:** Общий шаблон. Без параметров, без специфики.

**Шаг 2 — улучшенный запрос (показываем разницу):**
```
РОЛЬ: Ты — инженер по освещению с опытом проектирования офисов.
КОНТЕКСТ: Офис 500 м², open space, 60 рабочих мест, 8 переговорок, 
          2 кухни, коридоры. Работа 24/7 (2 смены).
ЗАДАЧА: Составить ТЗ на поставку и монтаж светильников LED.
ФОРМАТ: 
  1. Общие требования (площадь, высота потолков, освещённость)
  2. Технические параметры (таблица: зона, тип, мощность, 
     цветовая температура, количество)
  3. Требования к поставщику (опыт, гарантия, сертификаты)
  4. Условия поставки и монтажа (сроки, этапы, оплата)
  5. Форма заявки (таблица для заполнения поставщиком)
ОГРАНИЧЕНИЯ: Только LED, экономия энергии ≥ 40% vs люминесцентные.
```
**Результат:** Готовое ТЗ с таблицами и параметрами.

**Шаг 3 — Eval (улучшаем):**
```
Оцени ТЗ 1–10. Что не учтено для 24/7 работы? 
Какие дополнительные требования нужны для кухонь?
```

## Слайд 11: Демо 2 — Конкурентный лист из 3 КП

### Сценарий: получили 3 ответа от поставщиков

**Данные:**
| Поставщик | Цена | Срок | Гарантия | Условия | Монтаж |
|-----------|------|------|----------|---------|--------|
| А | 1250 ₽/шт | 3 дня | 2 года | 50/50 | 300 ₽/шт |
| Б | 980 ₽/шт | 14 дней | 1 год | 100% предоплата | Нет |
| В | 1100 ₽/шт | 7 дней | 3 года | 30/70 | 250 ₽/шт |

**Промпт:**
```
РОЛЬ: Ты — аналитик закупок.
КОНТЕКСТ: Внутренняя коммерческая закупка светильников LED.
ЗАДАЧА: Сформировать единый конкурентный лист.

Данные: [таблица выше]

Требования:
1. Таблица сравнения (поставщик, цена, срок, гарантия, оплата, монтаж, итого за 50 шт)
2. Критерии оценки (веса: цена 40%, срок 20%, гарантия 20%, условия 20%)
3. Рейтинг по каждому критерию (1-5 баллов)
4. Итоговый рейтинг (взвешенная сумма)
5. Рекомендация с обоснованием (не "дешевле", а "лучший баланс цена/риск")

ФОРМАТ: Таблицы с разделителями |. Только факты.
```

**Eval:**
```
Какие риски не учтены при сравнении? 
Что ещё проверить у поставщиков? Какие скрытые затраты?
```

## Слайд 12: Демо 3 — Поиск поставщиков

### Сценарий: нужно найти поставщиков кабеля ВВГнг-LS в Москве

**Промпт:**
```
РОЛЬ: Ты — закупщик электротехнической продукции.
ЗАДАЧА: Составить список потенциальных поставщиков.

Требования:
- Продукт: кабель ВВГнг-LS (силовой, негорючий, малодымный)
- Регион: Москва и МО (доставка до складов на МКАД)
- Требования: собственное производство или прямые договоры с заводами,
  гарантия, сертификаты пожарной безопасности

ФОРМАТ: Таблица (компания, сайт, телефон, ассортимент, плюсы, минусы, приоритет 1-5)
ОГРАНИЧЕНИЯ: Только реальные компании, работающие в РФ. 
Не выдумывай контакты. Если не уверен — укажи [уточнить].
```

**⚠️ Важное предупреждение:**
> ИИ может выдумать компании, сайты или телефоны, которых не существует. 
> **Всегда проверяйте реальность найденного:**
> - Откройте сайт — работает ли?
> - Позвоните по телефону — отвечают ли?
> - Проверьте через госреестры (ЕГРЮЛ, сайт ФНС)
