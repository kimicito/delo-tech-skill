# Смета по ФЕР-2020 — БИМ-методика

## 🔄 Пайплайн: Полный flow

```
[Чертежи PDF] ──▶ [drawings-to-vor] ──▶ [ВОР.xlsx] ──▶ [smeta] ──▶ [Смета.xlsx]
     │                  Stage 1              │            Stage 2
     │                                       │
     ▼                                       ▼
  PDF/PNG/JPG                          Единственный вход
  Масштаб, спецификации                для сметы
```

**Контракт между stages:**
- `drawings-to-vor` выход: `ВОР.xlsx` (позиции, ед.изм, количества)
- `smeta` вход: `ВОР.xlsx` + `knowledge_base.md` (коэффициенты)
- **Ничего не добавлять в смету, чего нет в ВОР!**

**Репозитории:**
- Stage 1: `github.com/kimicito/drawings-to-vor`
- Stage 2: `github.com/kimicito/openclaw-workspace/skills/smeta` (этот файл)

## ⚠️ КРИТИЧЕСКИЕ ПРАВИЛА (нарушение = 10-100× ошибка)

### 1. Метод расчёта — только БИМ

| Метод | Что делать | Ошибка если нет |
|-------|-----------|-----------------|
| **БИМ** (базисно-индексный) | Разделять по статьям: ОТ, ЭМ, М | Общий индекс → занижение в 7× |
| **Методика 2** | Индексы по статьям: INDEX_ZP, INDEX_MACH, INDEX_MAT | Общий INDEX_SMR → неверно |
| **Приказ 421/пр** | НР/СП от ФОТ, не от прямых | 15%/12% от прямых → занижение в 10× |

### 2. Статьи затрат (всегда разделять)

| Статья | Сокращение | Индекс | Что входит |
|--------|-----------|--------|-----------|
| **Оплата труда рабочих** | ОТ (или ОЗП) | INDEX_ZP ≈ 60-70 | Зарплата рабочих |
| **Эксплуатация машин** | ЭМ | INDEX_MACH ≈ 15-20 | Амортизация, топливо |
| **Материалы** | М | INDEX_MAT ≈ 8-10 | Материалы, изделия |
| **Зарплата машинистов** | ЗПМ | INDEX_MACH | Внутри ЭМ |
| **Транспорт затрат** | ТЗ | INDEX_MAT | Доставка |

**Формула текущей цены (БИМ):**
```
Текущая сумма = (ОТ×INDEX_ZP) + (ЭМ×INDEX_MACH) + (М×INDEX_MAT)
```

### 3. НР и СП — от ФОТ, не от прямых

| | Неправильно | Правильно |
|---|------------|-----------|
| **База** | 15%/12% от прямых затрат | % от ФОТ (фонд оплаты труда) |
| **Норматив** | Типовые 15%/12% | Шифр по типу работ (Пр/812-016.0-1, Пр/774-016.0) |
| **Пример** | НР = 15% × 10 000 = 1 500 | НР = 121% × ФОТ = 2572 тыс.руб. |

### 4. Поправки (коэффициенты условий работ)

**Правило:** Не одна поправка, а **две-три**, с разными коэфф. по статьям.

| Поправка | ОТ | ЭМ | М |
|----------|-----|-----|-----|
| **П.58 пр.б** (действующее здание) | 1.15 | 1.25 | 1.25 |
| **Прил.10 т.5 п.1.2** (ограничения) | 1.35 | 1.35 | 1.35 |
| **Итоговая** | 1.55 | 1.69 | 1.25 |

**Применяется к базовой цене ДО индексирования.**

### 5. ФССЦ — материалы отдельно

**Правило:** Материалы внутри ФЕР — только монтажные. Основные материалы добавляются отдельно через ФССЦ.

**Пример:**
- ФЕР20-02-002-01 — монтаж решётки (без стоимости решётки)
- ФССЦ 19.2.03.07-0008 — стоимость решётки 150×150 = 12.84 руб/шт

### 6. ВОР = единственный источник объёмов

**Правило:** Всё, что в ВОР → должно быть в смете. Всё, что в смете → должно быть в ВОР.

**Если код ФЕР неизвестен:** Пишем «УТОЧНИТЬ», не придумываем.

## Пайплайн составления сметы

### Шаг 0: Проверить актуальность нормативов (КРИТИЧЕСКО)

**Перед каждой сметой — проверить:**

1. **Индексы ФГИС ЦС** — актуальны ли? (проверить на fgiscs.minstroyrf.ru)
2. **Письма Минстроя** — вышло ли новое письмо с индексами?
3. **Нормативные базы** — актуальная ли редакция ФЕР/ГЭСН?

**Источники для проверки:**
- [ФГИС ЦС — Индексы](https://fgiscs.minstroyrf.ru/frsn/reference/indexes/74a617f7-36bc-4990-a3aa-29ff20b9c0f4)
- [Письма Минстроя](https://fgiscs.minstroyrf.ru/prices) — раздел "Нормативные документы"
- [Официальное опубликование](http://publication.pravo.gov.ru) — приказы и изменения

**Если индексы устарели:**
- Запросить у пользователя свежие данные
- Или проверить ФГИС ЦС (если доступен)
- НЕ использовать старые индексы!

### Шаг 1: Прочитать ВОР
- **ВОР приходит из Stage 1** (`drawings-to-vor`)
- Вынести все позиции: наименование, единица, количество
- Ничего не добавлять, ничего не убирать
- **Если ВОР не готов — остановиться, вернуться к Stage 1**

### knowledge_base.md (shared с drawings-to-vor)

Файл `knowledge_base.md` содержит коэффициенты и правила, используемые в обоих stages:
- Коэффициенты уплотнения (ПГС ×1.18×1.01)
- Правила опалубки (автодобавление к бетону)
- Вспомогательные работы (ограждение, перевозка, отвал)
- Типовые элементы (умножение на количество)

**Путь:** `skills/smeta/knowledge_base.md` (symlink к `skills/drawings-to-vor/knowledge_base.md`)

## Шаг 2: Подобрать коды ФЕР
- Для каждой позиции ВОР найти соответствующий код ФЕР-2020
- Если не знаешь код — «УТОЧНИТЬ»
- Использовать PDF сборники или ГРАНД-Смету для поиска

### Шаг 3: Рассчитать базовые цены
- Для каждой позиции: базовая цена ФЕР-2020 (руб. 2000 г.)
- Разбить на статьи: ОТ, ЭМ, М

### Шаг 4: Применить поправки
- Найти все применимые поправки (п.58, Прил.10, др.)
- Применить с разными коэфф. по статьям

### Шаг 5: Применить индексы
- INDEX_ZP для ОТ
- INDEX_MACH для ЭМ
- INDEX_MAT для М
- **НЕ использовать общий INDEX_SMR**

### Шаг 6: Добавить ФССЦ
- Для каждого материала — отдельная позиция ФССЦ
- Количество = объём из ВОР

### Шаг 7: Рассчитать НР и СП
- Найти шифр по типу работ
- НР = %_НР × ФОТ
- СП = %_СП × ФОТ

### Шаг 8: Сформировать итоги
- Прямые затраты (по статьям)
- НР, СП
- Всего по смете
- С НДС (если нужно)

## 🔍 Шаг 9: Проверка eval (ОБЯЗАТЕЛЬНО — без этого смета не готова)

**Запускать перед каждой отправкой.** Без eval — смета считается черновиком.

```bash
python3 eval_smeta.py --smeta смета.xlsx --vor вор.xlsx
```

**Что проверяет eval (FAIL = отправлять нельзя):**
1. ✅ Все позиции ВОР есть в смете
2. ✅ Количества совпадают (в пределах 1%)
3. ✅ Нет лишних позиций (не из ВОР)
4. ✅ Нет позиций «УТОЧНИТЬ» без пометки
5. ✅ Присутствуют НР и СП (не пустые)
6. ✅ Использованы индексы по статьям (ОТ, ЭМ, М), а не общий INDEX_SMR
7. ✅ НР/СП рассчитаны от ФОТ (а не от прямых затрат)
8. ✅ Есть ФССЦ-позиции для основных материалов
9. ✅ Поправки применены до индексирования (не после)
10. ✅ Нет пустых строк или дублей кодов ФЕР

**Если eval FAIL:**
- Исправить ошибки
- Перезапустить eval
- Только потом отправлять пользователю

**Интеграция в pipeline:** eval — это **встроенный 4-глазый контроль**. Даже если я уверен, что всё правильно — eval проверяет объективно.

## Быстрый чек-лист (перед отправкой) — ОБЯЗАТЕЛЬНЫЙ порядок

**Без eval смета = черновик. Отправлять нельзя.**

- [ ] **Индексы проверены** — актуальны ли? (дата последнего письма Минстроя)
- [ ] ВОР сверен — все позиции в смете
- [ ] Индексы по статьям (ОТ, ЭМ, М), не общий INDEX_SMR
- [ ] Поправки применены с разными коэфф. по статьям (до индексирования)
- [ ] НР/СП от ФОТ, не от прямых
- [ ] ФССЦ добавлены для материалов
- [ ] Нет «УТОЧНИТЬ» без пометки
- [ ] **eval запущен и пройден без FAIL**

## Обновление нормативов

**Письма Минстроя выходят ежеквартально** (обычно в первый месяц квартала).

**Как следить:**
1. Подписаться на рассылку Минстроя (если есть)
2. Проверять fgiscs.minstroyrf.ru ежеквартально
3. Проверять publication.pravo.gov.ru на изменения в приказы

**При выходе нового письма:**
1. Обновить [[Индексы ФГИС ЦС]] в wiki
2. Обновить SKILL.md (новые значения индексов)
3. Проверить все открытые сметы — не устарели ли?
